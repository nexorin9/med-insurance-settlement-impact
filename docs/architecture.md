# 架构、状态机与图算法说明

> 面向信息科排障与二次开发；产品说明见 `README.md`，命令参考见 `docs/cli.md`。

## 1. 分层

```text
App（桌面窗口 + 托盘 / CLI 子命令）
  └─ service/        九步主流程、状态机、定时重算
       ├─ sqlparse/   Oracle 视图 SQL → 四类列级边 + 待人工核对清单
       ├─ lineage/    字段级双方向邻接表 → 拓扑序 → 下游可达双口径 → 影响记录 / 证据链
       ├─ catalog/    193 项清单字段字典、四分区校验、字段与列三级对齐
       ├─ attribution/ 单一 ModelGateway、严格 JSON 契约、六类错误与降级
       ├─ adapter/    JDBC 只读、台账 GET/POST、幂等回写、权限闸门
       ├─ store/      SQLite 状态、不可变审计链、失败事件落盘、运行统计
       └─ report/     厂商说明、影响面 CSV、两版差异回放
  └─ ui/            设计 token、三栏工作台、详情抽屉、托盘、三态与响应式
```

服务层**不依赖任何 Swing / AWT 类**；界面只消费纯数据模型与回调，因此 CI 无显示环境也能跑全部业务逻辑与导出。

## 2. 九步主流程与降级映射

| 步 | 动作 | 失败时 |
|----|------|--------|
| 1 | 读取视图定义（JDBC 只读 / 输入 SQL） | 库不可达 → 沿用上次已存图并标注图已过期，不推算新结论 |
| 2 | SQL 解析（四类列级边） | 按行列号报告 + 待人工核对清单，本轮不推算新结论 |
| 3 | 图构建（跨视图消费链、同名消歧） | 跳过未解析边，不臆造节点 |
| 4 | 下游可达（strict / conservative） | 环安全遍历，环边显式标注 |
| 5 | 清单对齐（字典 193 项） | 字典不可用 → 清单字段区空并报错，不按空字典算 |
| 6 | 归因（确定性基线优先，模型只处理词面不一致候选） | 模型不可达 → DEGRADED 且禁止回写 |
| 7 | 待确认（PENDING_CONFIRM） | 未全部确认时不允许回写 |
| 8 | 人工确认（写 confirmed_by / confirmed_at） | 只能由人推进 |
| 9 | 幂等回写（权限 + 开关 + 确认三重闸门） | 退避重试 ≤2 次后置待回写并导出变更单 |

## 3. 状态机

```text
PARSED → COMPUTED → ATTRIBUTED → PENDING_CONFIRM → CONFIRMED → WRITTEN_BACK
   └→ DEGRADED（模型不可达，仅列名匹配）      └→ AMBIGUOUS（歧义挂起，待裁决）
                                              └→ PENDING_WRITEBACK（回写失败）
```

- `CONFIRMED` 只接受 `Actor.HUMAN`；`WRITTEN_BACK` 拒绝 `Actor.MODEL` 与 `Actor.TOOL`。
- 非法跃迁抛异常，消息含「从 X 不能到 Y」，且不落库、不写审计。
- 撤回只追加一条撤回审计条目，状态回到 `PENDING_CONFIRM`，**不物理删除**原记录。
- 每次合法跃迁写 SQLite 并追加审计条目，状态跨重启留存。

## 4. 图算法与基线对比

- 图：`Map<FieldKey, Set<FieldKey>>` 的 UPSTREAM / DOWNSTREAM 双表，字段键规范形式 `VIEW.COLUMN`；同一对节点的多条不同 `edge_kind` 合并为一个多重 kind 集合，去重不丢信息。
- 拓扑序：Kahn 排序 + 环检测；环内节点单独标记，排序不中断，环边在结果里显式标注。一跳 `parents` 与传递闭包严格区分。
- 下游可达：沿 DOWNSTREAM 的 BFS，visited 入队时登记，结果为稳定同序的 `LinkedHashSet`；严格口径只走 `DIRECT / DERIVED / AGGREGATE`，保守口径并入 `FILTER`。
- 跳数：输出每字段最短跳数与最短路径（逐跳带 `edge_kind`）；跳数 ≥3 标记需人工确认，不自动判定实质影响。
- 基线对比：源思路是「无向连通分量」（合并上下游），会把上游也框进受影响集。本产品只取下游可达子集，`docs/lineage-baseline-benchmark.md` 给出 12 张样例图上两种口径的受影响字段数、多报字段样本、耗时与复跑命令。断言本产品集合 ⊆ 基线集合，且存在多报 >0 的用例。

## 5. 幂等、审计与凭据

- 幂等键 `sha256(view_name|sql_digest|changed_field)`，其中 `sql_digest` 是规范化 SQL（统一空白与大小写、剔除注释）后的 sha256，仅空白与注释差异视为同一段 SQL。该键同时作 HTTP `Idempotency-Key` 头与台账覆盖键。
- 审计条目只增不改，可按视图 / 批次 / 操作人回查；内容含口径、判定、确认人、是否回写、是否撤回，且不含凭据字面量与患者明细。
- 失败事件按每行一个 JSON 落 `failed_events.log`，字段含时间、视图、阶段、错误码、错误摘要、输入摘要、幂等键，可按幂等键或视图筛选并重放定位。
- 凭据只从 9 个环境变量读；异常、栈与日志统一过脱敏器；台账返回的敏感片段不在界面明文展示。

## 6. 模型边界

- 确定性基线 100% 可复现：SQL 解析、列级边、图、拓扑序、下游可达、列名精确 / 别名匹配、置信度阈值、幂等与审计。
- 模型只处理词面不一致的候选边，输出严格 JSON：`affected[] {list_field, section, source_column, verdict, confidence, reason_zh}` + `summary_zh`；verdict 限于实质受影响 / 同名不同义 / 疑似 / 不可判定，confidence ∈ [0,1]。schema 不合规即失败，不做尽力解析。
- 模型不可达、超时、返回不合规 → `DEGRADED`，界面标注归因未生成，双层拦截回写；模型**不得推进任何业务状态**。
- 业务层只依赖 `ModelGateway` 接口，替换第二个 OpenAI-compatible 实现不需要改业务代码；本地协议替身只存在于测试层。

## 7. UI 与 headless

- 设计 token 集中在 `ui/Theme`：冷灰底 `#F4F6F9`、深蓝主色 `#1F4E79`、语义色、8px 栅格、五级字号、中文字体 fallback 链、等宽字体渲染字段名与幂等键；按钮四态与表格行三态可枚举。
- 三栏工作台顶栏三个数与服务层运行统计回调绑定，不轮询数据库；详情抽屉逐跳展示证据链、口径标签、置信度与待人工核对条目。
- 托盘常驻，关窗只隐藏不退出；托盘不可用时降级为隐藏窗口 + 状态栏提示并明确告知；摘要变化触发气泡，同视图短时间多次变化合并为一条。
- 无显示环境进入 headless 模式：不创建窗口，全部 CLI 子命令可跑，影响面计算与 CSV / 说明导出完全脱离界面。两档响应式 1280（三栏）/ 768（左树折叠 + 详情覆盖层）均无横向滚动条。
